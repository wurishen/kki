# Novel Injector（小说注入器）

一个 SillyTavern（酒馆）第三方扩展：**让 AI 先把一部长篇小说读完，再在你聊天时按需把用得上的原著资料喂给它。**

> 你想接着某本小说的剧情往下写，但 AI 记不住前面发生过什么、谁是谁、这世界的规矩是什么——这个插件就是来解决这个问题的。

## 一、它是怎么工作的

分三步：

```
① 你上传小说（.txt / .mobi）
        ↓
② 插件调用 AI 逐段"清洗"：把原文压缩成精华，并提取剧情节点、角色、世界观、文风
        ↓
③ 你正常聊天 → 插件挑出当前用得上的资料，注入到发给 AI 的上下文里
```

⚠️ **原著是参考书，不是剧本。** 插件不会逼 AI 照抄原著。你改剧情、改人物关系都行，AI 会顺着你的改动走；「剧情偏差分析」还会专门把你造成的既成事实记下来，防止 AI 后面又按原著硬来。

**你需要准备一个 OpenAI 兼容的 AI 接口**（地址 + Key + 模型），用来读小说。这一步是必需的——插件本身不含模型。想用语义检索的话，还需要一个 Embedding 接口（可选）。

## 二、安装

### 方法一：插件市场安装（推荐）

在 SillyTavern 的第三方扩展安装入口粘贴：

```
https://github.com/ZZZa-o/novel-injector
```

装完**刷新页面**，点顶部工具栏的📖书本图标打开面板。

### 方法二：手动安装

把整个仓库放进酒馆扩展目录：

```
SillyTavern/public/scripts/extensions/third-party/novel-injector
```

目录里应有：

```
manifest.json    index.js    template.html    style.css    lib/    README.md
```

放好后刷新或重启酒馆。

> 顶栏图标可以在扩展菜单里的「显示/隐藏顶栏图标」开关掉（默认显示）。

## 三、快速上手

### 最短可用路径（不做向量化）

只要这 4 步就能跑起来：

1. **处理** 页 → 上传 `.txt` 或 `.mobi` 小说；
2. 点 API 设置齿轮 → 填**清洗 API** 的地址、Key、模型（必需）；
3. 点 **开始全自动清洗**，等它逐段读完（可暂停、可续跑）；
4. **阶段** 页 → 打开想让 AI 参考的阶段 → 回聊天窗正常发消息。

> 💡 没做向量化也能用：未向量化的阶段会直接注入剧情节点或压缩原文，只是不如语义检索精准，但省事。

### 完整路径（加上语义检索与穿书）

5. **剧情** 页 → 点 **划分阶段**，把小说切成若干段（比如按卷、按篇章）；
6. **处理** 页 → 填**向量 API**（Embedding 接口）→ 选阶段 → 向量化；
7. **阶段** 页 → 开启需要的阶段，确认向量状态；
8. 想玩「我穿进这本书」→ **剧情** 页开启穿书模式，用状态栏管理剧情进度。

## 四、五个页面分别管什么

面板底部有 5 个页签：

| 页签 | 管什么 |
|---|---|
| **处理** | 上传小说、清洗、API 设置、文风生成、向量化、注入参数 |
| **剧情** | 偏差分析、穿书模式、世界设定、剧情节点（时间轴/主线/支线/转折）、阶段划分 |
| **角色** | 用户代入、角色人设、开关注入、AI 更新人设 |
| **阶段** | 开关阶段、生成阶段标题与概括、角色演绎提示词 |
| **设置** | 插件总开关、全局提示词、外观主题、小说库、导入导出、清理 |

### 处理页

**清洗（读小说）**
按设定大小把原文分段（默认每段 **100 KB**），逐段交给 AI，每段产出两样东西：

- **压缩正文**——按时间顺序保留关键剧情、人物关系、时间地点、因果与转折；
- **结构化清单**——这段登场了谁、发生了什么事、有哪些主线/支线/转折节点。

支持暂停、跳过当前段、续跑、单段重洗、批量重试失败段。单段请求超时会自动重试，最多 3 次后标记为失败。已清洗完的内容不会因为你改了分段大小就白读。

**API 设置**

| 项目 | 用途 | 默认值 |
|---|---|---|
| 清洗 API 地址 | 读小说、提剧情角色、生成世界观与文风 | `https://api.openai.com/v1/chat/completions` |
| 清洗模型 | 同上 | `gpt-4o` |
| 向量 API 地址 | 生成 Embedding 索引（可选） | `https://api.openai.com/v1` |
| 向量模型 | 同上 | `text-embedding-3-large` |
| 请求超时 | 每段请求最长等待 | 15 分钟 |
| 每分钟请求上限 | 清洗限速 | 3 次/分 |
| 并发数 | 清洗、阶段概括、AI 人设共用 | 1（串行） |
| 向量限速 / 并发 / 批量 | 向量化专用 | 3 次/分 / 1 / 每批 16 块 |

支持点按钮拉取模型列表直接选。

**文风**
三种取样方式：从原文自动采样（默认取 1000 字）、手动粘贴范文、指定某一段作样本。生成的「文风执行指南」可编辑，清空即停止注入。

**向量化**
把清洗好的内容按 **500 字符**切块，调 Embedding 接口生成索引，存进浏览器 IndexedDB。做完后 AI 能按语义找到相关原文片段，而不是靠猜。

### 剧情页

**剧情偏差分析**
对比「你聊到哪了」和「原著写到哪」，算出偏离程度，并把**已经发生的新事实**记录下来（角色已死、身份已暴露、关系已改变……），注入给 AI 当作分支现实约束。

- 默认**手动触发**，一次分析最近 10 条消息；
- 可开启自动更新（默认关闭），开启后每 10 楼自动跑一次；
- 分支事实列表按**面板显示的楼层**升序排列——事实若被后续剧情改写，会移动到改写发生的楼层位置。

**穿书模式**——见 [第七章](#七穿书模式)。

**世界设定**
把世界观分类整理并注入。内置三个默认大类：

| 分类 | 说明 | 默认 |
|---|---|---|
| 世界边界 | 这世界存在什么、不存在什么（科技水平、特殊物质、超自然现象） | 开启 |
| 特殊机制 | 独有规则与超自然机制及其限制（修炼/异能/系统等） | 开启 |
| 社会规则 | 权力结构、社会阶层、法律与现实的差异 | 关闭 |

每类可手动编辑、AI 单类生成、批量生成、单独开关注入。分类本身也可增删改。

**关键剧情**
剧情节点四个视图：**时间轴 / 主线 / 支线 / 关键转折**。支持增删改、拖拽排序、AI 修补支线关联。列表默认每页 20 条自动分页。

**阶段划分**
把剧情节点切分成阶段，是后续所有「按阶段开关」的基础。

### 角色页

**角色人设**
按 **主角 / 配角 / 反派 / 其他** 分类展示。可以：

- 单个或整类开关注入；
- 分别查看**原始人设**（清洗提取）和 **AI 更新人设**（AI 依据近期对话补充），并各自选择注入哪个；
- 手动增删改角色，字段含身份、外貌、性格、关系、性别、分类、首次登场阶段；
- 一键 AI 批量更新人设（可中途取消）：只有近期对话中**确实出现过该角色名字或可靠别名**时才会生成，证据不足直接跳过；请求失败会自动重试 3 次，结束后显示成功/跳过/失败的完整统计；
- **自动休眠**（默认开启）：切换阶段时自动关闭本阶段正文未出现的角色，主角与代入角色保留。

默认每页 20 个自动分页。

**用户代入角色**——见 [第八章](#八用户代入角色)。

### 阶段页

控制**哪些阶段给 AI 看**：单个开关、全开、全关；生成阶段标题与概括；编辑该阶段的**角色演绎提示词**；查看每个阶段的向量化状态。

### 设置页

- **插件总开关**——一键停用全部注入；重新开启时会自动恢复之前的穿书状态。
- **全局提示词**——三选一：`不使用` / `跟随酒馆主预设` / `使用插件内置`（默认内置）。内置分头部、尾部两条，位置深度可分别设置。跟随预设时插件会明确标注「这是后台整理任务，不是角色扮演」，尽量不干扰你的角色卡。
- **外观主题**——主色、次色、强调、警示、背景、文字色可调（取色器或 `#RRGGBB`）。内置三套预设：**默认**、**星糖梦簿**、**星糖梦簿·夜间**。可新建、保存、导入导出、删除自定义主题。另有「跟随美化」「去除边框」「去除卡片」等开关。
- **小说库**——当前进度存成快照，一本小说一个。支持保存、加载、更新、重命名、删除，默认每页 20 条。
- **导入导出**——见 [第九章](#九数据存在哪怎么备份)。
- **清理**——清当前小说向量缓存 / 清除全部数据（二次确认）。
- **自动保存**——**默认关闭**，需手动开启；开启后改动会防抖保存。

## 五、核心概念：阶段与向量化

理解这两个概念，插件就基本会用了。

### 阶段（Stage）

阶段是把长篇小说切成的若干区段，**是注入的开关单位**。你在剧情页划分阶段后：

- 阶段页可以逐个决定「这段给不给 AI 看」；
- 向量化按阶段独立进行；
- 每个阶段可以有自己的标题、概括、角色演绎提示词。

> 改动阶段划分后，受影响阶段的向量索引会重置，需要重新向量化。

### 两种注入方式

一个开启的阶段，会走以下两条路之一：

| 阶段状态 | 注入方式 | 说明 |
|---|---|---|
| **已向量化** | 语义召回 | 按当前对话内容检索最相关的原文片段，精准省 token |
| **未向量化** | 直接注入 | 把该阶段资料整段塞进去 |

未向量化阶段有两种喂法（处理页「未向量注入」设置）：

| 模式 | 内容 | 取舍 |
|---|---|---|
| **剧情节点**（默认） | 主线/支线/转折要点 | 省 token |
| **压缩原文** | 该阶段的压缩正文 | 信息全，但更费 token |

**塞不下怎么办？** 直接注入有 token 上限（默认 32000）。超出时插件按以下顺序退让：

1. 优先保**当前阶段**，其余阶段按与当前阶段的距离由近到远排队；
2. 放不下完整内容的阶段，退化成「阶段概括」；
3. 还放不下就整个跳过；
4. 最终注入的内容按阶段顺序重排，并在页面上显示本轮实际喂了多少、省略了哪些。

### 向量召回怎么选片段

召回时插件取最近几条对话（默认 3 条）作为查询，**越新的权重越高**（每往前一条权重 ×0.5），并把当前阶段的剧情节点也拼进查询里。默认返回相似度 ≥ 0.5 的前 3 个片段。

可以设「消息内容标签」只提取消息中某个标签内的文字（例如填 `content` 就只取 `<content>...</content>` 里的内容）作为检索依据，避免思维链、状态栏等噪音干扰召回。

## 六、插件到底往上下文里塞了什么

插件在酒馆生成提示词时挂钩，按需注入下面这些块。每块**都能单独设置插入位置、深度、消息角色**，也都会在你不需要时自动省略。

| 注入块 | 标签 | 触发条件 | 默认位置 | 默认深度 | 默认角色 |
|---|---|---|---|---|---|
| 向量召回 | `[小说原著相关片段·向量召回]` | 有已向量化的开启阶段 | 聊天内 | 4 | system |
| 阶段剧情 | `[小说剧情节点]` 或 `[小说压缩原文]` | 有未向量化的开启阶段 | 聊天内 | 4 | system |
| 角色人设 | `[原著角色人设]` | 有启用的角色 | 主提示前 | 4 | system |
| 世界设定 | `[世界设定]` | 有启用且非空的分类 | 主提示前 | 4 | system |
| 偏差约束 | `[当前剧情偏差约束]` | 已做过偏差分析 | 主提示前 | 0 | system |
| 文风指南 | `[文风执行指南]` | 已生成文风 | 主提示前 | 4 | system |
| 全局提示词 | 头部 / 尾部两条 | 设为「内置」时 | 主提示前 / 聊天内 | 0 | system |
| 穿书提示词 | 开场·推进 / 持续 | 穿书模式开启 | 聊天内 | 1 | system |

**插入位置**三选：`主提示前` / `主提示后` / `聊天内`；**消息角色**三选：`系统` / `用户` / `助手`。

> 插件总开关关闭时，以上全部不注入。

## 七、穿书模式

适合「我穿进这本书」的玩法：围绕**当前剧情节点**管理推进节奏。

**开启位置**：剧情页，「世界设定」上方。

### 它做了什么

- 正文里挂一个**进度状态栏**（或弹窗，显示方式可切换），展示当前所处节点、所在阶段、归档进度；
- 勾选节点表示「这段推进完了」，归档后自动前进；
- **注入节点由归档进度推导**——取当前阶段内第一个未归档且未锁定的节点。整个阶段归档完会停在该阶段末节点，**不会自动跨阶段**（需要你手动切换阶段）；
- 穿书模式下，未向量阶段的直接注入**只注入当前阶段**，避免剧透后文。

### 可用功能

| 功能 | 说明 |
|---|---|
| **推演后文** | 让 AI 给出三个不同方向的后续建议，点一下填进输入框 |
| **暂停** | 暂停后不再注入开场/推进/持续提示词，剧情不推进（沉浸提示词仍由自身开关控制） |
| **沉浸模式** | AI 只写 `<user>` 该知道的、被明确告知过的信息，不提前剧透秘密与身份 |
| **轻量召回** | 向量召回时改用精简的节点上下文作查询 |
| **提示词编辑** | 推进 / 持续 / 沉浸 / 推演 四套提示词均可编辑，支持一键恢复默认 |

穿书进度**按聊天独立保存**，换聊天互不影响。

## 八、用户代入角色

想让「我扮演的就是原著里的某个角色」，在角色页开启此功能并选中角色。**两种代入方式**：

| 模式 | 效果 |
|---|---|
| **替换原角人生**（默认） | 该角色**不再作为独立 NPC** 注入，其名字在注入文本中替换为 `<user>` |
| **扮演原角本人** | 该角色资料作为 `<user>` 的既有身份与人物基础注入，标记为「用户扮演原著角色资料」 |

其余角色仍按 NPC 演绎。未开启此功能时，插件会明确告诉 AI：原著角色默认是独立 NPC，不要把原著角色的经历与选择自动套到 `<user>` 头上。

**关于称呼**

- 候选称呼来自清洗时收集的角色别名（外号、称呼、身份称谓），按出现阶段分组显示；
- 可手动添加、编辑、删除；
- **每个聊天独立保存**配置。

> ⚠️ 替换只发生在**注入层**：你的小说原文、剧情数据、角色数据、向量索引一律不改，因此**不影响向量召回**。

## 九、数据存在哪、怎么备份

| 数据 | 存储位置 |
|---|---|
| 设置、API 配置、小说库索引、阶段开关、主题 | 酒馆 `extension_settings` |
| 剧情、角色、称呼、清洗状态、文风 | 酒馆 `user/files` 下的 `*_core.json` |
| 清洗后的压缩正文 | 酒馆 `user/files` 下的 `*_chunks.json` |
| 阶段索引与节点映射 | 酒馆 `user/files` 下的 `*_stages.json` |
| 向量索引 | 浏览器 IndexedDB（库名 `NovelInjectorVectors`） |
| 穿书进度 | 当前聊天的第一条消息上 |
| 用户代入配置 | 当前聊天的 `chat_metadata` |

服务端重数据文件按 `ni_<快照名拼音>_<随机key>_<部分>.json` 命名。

### 导入导出

**导出 ZIP** 包含设置、剧情角色数据、阶段索引与向量（二进制），**不含** API 地址、Key 和模型名——可以放心分享。

**导入**支持新版 ZIP 与旧版 JSON。导入**不会覆盖**你当前的小说，而是作为一本新快照加入小说库，需要手动加载才会切换过去。

> 向量数据体积较大，导出前可按需先清理不用的向量缓存。

## 十、常见问题

**不做向量化能用吗？**
能。未向量化的阶段会直接注入剧情节点（默认）或压缩原文，只是不如语义召回精准。

**改了阶段划分要重新向量化吗？**
要。阶段变动后受影响阶段的向量索引会重置，重新选中再跑一次即可。

**为什么「用户代入」里没自动出现几个称呼？**
称呼来自清洗时收集的角色别名。用旧版本清洗的小说可能没收集到，重新清洗相关段落即可；手动添加的称呼立即可用。

**用户代入会影响向量召回吗？**
不会。替换只在注入层发生，原文与向量数据不变。

**导入备份会覆盖我现在的小说吗？**
不会。只会新增一本快照，手动加载才切换。

**导出会泄露我的 API 配置吗？**
不会，导出文件不含接口地址、模型和 Key。

**清洗总是失败？**
依次检查接口地址、Key、模型名、超时时间和限速设置。单段失败可以单独重洗那一段，也可以点「重试失败分段」批量重来。并发调高容易触发限速，建议先保持默认串行。

**AI 更新了人设但页面没显示？**
多半是模型返回被截断（`finish_reason: length`），半截的 JSON 插件不会保存。插件会识别截断、空响应和 JSON 异常并**自动重试 3 次**（共尝试 4 次，每次间隔 250 毫秒），仍失败会显示具体是哪个角色、失败原因。换个输出上限更高的模型通常能解决。

**某个角色被跳过了，没有重试？**
这是有意为之：如果近期对话里没有直接出现该角色的名字或可靠别名，插件会**直接跳过**而不消耗请求去重试，并提示「近期对话没有直接出现「X」或可靠别名」。这是为了防止 AI 把发生在别人身上的事安到这个角色头上。

**向量化失败？**
检查向量 API 的地址、Key、模型名。被限速就调低每分钟请求数或批量大小。可以用「🔍诊断」查看 IndexedDB 里实际存了什么。

**`.mobi` 传不进去？**
插件内置的 MOBI 解析器支持**无压缩**和 **PalmDoc 压缩**两种格式。以下情况会明确报错，需要你先转成 `.txt`：

- 带 DRM 加密的 MOBI；
- Huff/CDIC 压缩的 MOBI；
- 其他未知压缩类型。

**穿书状态栏不显示 / 显示异常？**
先确认穿书模式已开启、显示方式选的是「状态栏」。若 DOM 存在但画面空白，多半是浏览器毛玻璃合成层问题——插件已内置层隔离修复，遇到残留可先折叠再展开状态栏触发重绘。

## 十一、排查与技术细节

### 运行环境要求

- 需要 SillyTavern 环境，作为第三方扩展加载；
- 清洗接口需兼容 **OpenAI Chat Completions** 格式；
- 向量接口需兼容 **OpenAI Embeddings** 格式；
- 向量数据存于浏览器 IndexedDB（`NovelInjectorVectors`，版本 2，对象仓库 `chunks`）——**换浏览器或清空站点数据会丢失**，请用 ZIP 导出备份。

### 控制台日志前缀

排查时可在浏览器控制台按前缀过滤：

| 前缀 | 含义 |
|---|---|
| `[NI]` | 主流程（注入、清洗、向量召回） |
| `[NI-TB]` | 穿书模式（状态保存、节点推导、轨道自检） |

例如未向量阶段被 token 上限裁剪时，会打印实际注入的阶段与被省略的数量。

### 已知限制

- 直接注入的 token 估算按 **1.5 字符/token** 折算，属于估算而非精确计数，实际消耗可能有偏差；
- 若酒馆的扩展提示词接口发生大改，注入位置与深度可能需要跟着调整；
- 自动保存默认关闭，长时间编辑建议手动保存或在设置页开启。
